# 「樹」位孿生：台北市樹木的數位孿生

🗳 **幫我們投票**：https://puma.taipei/hackathon/vote （10/24 17:00 開放、10/31 18:00 截止）・試玩模樹：https://taipei-tree-twin.pages.dev/treemulation/

台北市 16 萬棵登錄樹木，每一棵都有自己的頁面：民眾可以關心自己在乎的樹、看到它的前世今生；承做廠商施工前在現場核對樹牌、施工後回報，避免「該移植的樹被誤移除」再發生。

> 市政 debug 松（https://puma.taipei/hackathon ）題目 #1「把三千棵樹種回來」參賽作品。黑客松 demo，**大部分歷史事件與施工資料是模擬的**，畫面與下方表格都有標示。

## 為什麼做這個

**事實（附來源）**

- 臺北市政府 2026-07-12 新聞稿：2025 年移除樹木 3,164 株，其中 2,630 株屬自然死亡、腐朽、病蟲害、天災等合併分類。（[來源](https://www.gov.taipei/News_Content.aspx?n=74806083EBDF5A03&s=B9708CAABE7AAC15&sms=72544237BBE4C5F6)，官方數據）
- 東門市場一棵茄苳（報導描述約 40 年）：市府稱 2026 年 4 月會勘時原處置是「移植」（聯合報轉述為 4 月 23 日），5 月施工時被移除；2026-09-21 公園處公開承認疏失，裁罰與求償合計 325,210 元；09-22 宣布終止施工契約、政風室啟動調查。（[公園處 9/21 說明](https://www.gov.taipei/News_Content.aspx?n=74806083EBDF5A03&s=28831B7E8102EB08&sms=72544237BBE4C5F6)、[公園處 9/22 說明](https://www.gov.taipei/News_Content.aspx?n=74806083EBDF5A03&s=CB71C5F458062BF7&sms=72544237BBE4C5F6)、[聯合報 2026-09-21](https://udn.com/news/story/7323/9768138)）
- 目前沒有公開的逐樹移除紀錄；題目頁也註明逐年移除紀錄與原因尚未完整開放。

**各方主張（不是已證實的事實）**

- 市府主張移除多半基於公共安全與自然因素；這需要逐株診斷資料才能驗證，目前查不到。
- 東門案市府稱是「施工者未依原要求、監造不周」；調查尚未結案。

**我們的假說**

這類錯誤最可能斷在施工現場：沒有人在動手前核對「這棵是不是那棵、它被核准做什麼」。還沒被證實，驗證方式是調閱東門案施工日誌、監造紀錄與政風調查結果。如果成立，在現場加一道核對、讓結果即時公開，比事後罰款更能防止下一次。

## 功能模組（每個功能都是獨立產品）

- **功能目錄** `/features`：每個功能一張卡（完成度、demo 價值、給誰、資料狀態），可單獨開關、疊到地圖或開獨立頁 `/f/<功能 id>`。獨立頁固定六段：要解決什麼問題、給誰、怎麼用、資料與狀態、限制、100 天落地（局處／資料／經費／推廣）。
- **開關寫進網址**：`?f=planting,records` 只開這兩個；`?preset=demo`、`?preset=minimal` 套用預設組合（定義在 `app/features/index.js`，正式網址預設開哪些改一行即可）。沒有指定時依角色預設（manifest 的 `audience`）。
- **主地圖只放「看樹時順便要知道的事」**：需要專心算、專心讀的功能（樹冠負債、存量帳、首長儀表板、樹蔭公平、承諾追蹤、民意熱點、權責地圖、公開欄位清單、工程衝突預警、廠商履約、逐時曝曬）只做成獨立頁 `/f/<id>`，從功能目錄或導覽進入；它們的地圖疊加只在自己的頁面上打開。單棵樹頁只留一行「延伸分析」連結。
- **用途按鈕單選**：地圖上同時只有一種上色模式，圖例跟著按鈕出現。
- **第一眼重點卡**：每個角色進站先看到一個數字＋一句話＋一個主要按鈕（民眾：多少棵樹很久沒人拍；主管：本週要先複查幾棵；廠商：示範施工區有幾棵保留／移植；企業：認養了幾棵；規劃：推薦補植幾處；首長：幾棵樹的調查停在十年前）。
- **模擬施工案已拿掉**（2026-10-24）：原本三個虛構施工案、廠商查核示範與施工廠商角色，因不易理解而移除；東門茄苳的真實時間線保留。
- **引導故事**：企業認養（`#/story/esg`）改成 1/3、2/3、3/3 的步驟，開頭說明是誰（虛構）、哪棵樹、要示範什麼，結尾說明解決了什麼問題。
- **加功能**：新增 `app/features/<id>/index.js` 一份 manifest，在登錄表加一行；介面見 [docs/feature-api.md](docs/feature-api.md)。
- 角色 `/mayor` 首長（鍵盤 7）：首長儀表板。

## 怎麼跑

需求：Node.js 20（網站與伺服器無 npm 依賴，只用內建模組）；推薦種樹點分析另需 Python 3 與 shapely、pyproj、numpy。ESG 素材包（`app/downloads/esg/`）已預先產好；要重新產生才需要 `scripts/build-esg-pack.mjs` 用到的 Codex 內附工具與 Chrome，不在 build 流程內。

```bash
# 0. 下載原始資料到同一個目錄（檔名要一致）：
#    TaipeiTree.csv、TaipeiParkTree.csv、sidewalk-tree-holes.json（樹穴）、sidewalks.json（人行道）
#    來源網址見上方「真實資料」表與 data/raw/2026-10-13/manifest.json

# 1. 產生前端用的樹木資料 app/data/trees.json
node scripts/build-trees.mjs /path/to/raw

# 2. 產生推薦種樹點（輸出到 data/derived/，約 5 秒）
python3 -m venv .venv && .venv/bin/pip install shapely pyproj numpy   # 第一次
.venv/bin/python scripts/planting_candidates.py --raw /path/to/raw
cp data/derived/planting-candidates.json app/data/                    # 前端讀這一份

# 樹蔭×人流：另需 pyshp，輸入為捷運 OD、出入口座標、縣市界線，參數見腳本開頭說明
# .venv/bin/python -I scripts/shade_flow.py --raw /path/to/flow-raw

# 歷年影像與移動植栽（模擬）
# python3 scripts/build-imagery.py /path/to/shade-hackathon   # 需歷年影像研究的裁切圖
# python3 scripts/build-sim-planters.py

# 3. 啟動網站
PORT=8096 HOSTS=127.0.0.1 node server.mjs
# 打開 http://127.0.0.1:8096/
```

`server.mjs` 是 demo 用的小伺服器：提供靜態檔（gzip）和回報 API（`/api/events`），回報與照片存在 `runtime/`。

## 市府上任 100 天內落地（精簡版）

完整版：[docs/100-day-plan.md](docs/100-day-plan.md)。**100 天的目標是試辦啟動，不是全市上線。**

**局處**
公園處主責（樹籍標準、樹木編號、移除／移植核准資料、資訊網改版整合）；新工處提供樹穴與人行道圖資及道路工程處置計畫；各工程主辦機關把「施工前逐棵核對、施工後 3 個工作天內回報」寫進契約與驗收；施工與監造廠商在現場核對樹牌、拍照回報；資訊局負責架構、資安與帳號；文化局提供受保護樹木名錄；研考會列管 KPI；民政局與教育局協助里長、學校推廣。

**資料**
已有開放資料：行道樹及公園樹木分布圖、人行道樹穴、人行道範圍圖。已有但非開放格式：公園處樹木移除計畫審查專區與移植計畫審查（個案 PDF）、樹木異動專區、行道樹路燈資訊網移樹履歷查詢。缺口：逐樹移除紀錄（日期、原因、診斷、核准者）、移植計畫（原位置、移植地點、存活追蹤）、核准文號與樹木編號的對應、施工標案（範圍圖、廠商、監造、工期）、受保護樹木名錄、補植位置與存活率。規則：編號指樹不指樹穴、移植後沿用、移除後保留歷史；只在修剪、檢測、移植、移除、工程損害時更新，不要求全面重填。

**經費（情境試算，不是報價）**
小規模試辦（一個公園案＋一個道路工程案、數百株）100–200 萬元；跨機關正式版 500–900 萬元。類似標案決標 540–900 萬（嘉義 800 萬、公路局 897 萬、臺南 540 萬）；臺北現有樹木系統年維運 88–337 萬（第三方鏡像轉錄官方決標公告）。100 天內只需試辦級距，正式版排入下一年度預算。

**推廣計劃**
民眾：樹牌 QR 掃了就到那棵樹的頁面，「我的樹」看得到修剪與施工通報，搭配點數。廠商：寫進契約與驗收，沒有回報紀錄就不驗收。企業 ESG：認養與贊助贈品，但認養不排他，並要求部分資源回流樹蔭少的社區。里長與社區：試辦區說明會、社區巡樹志工。學校：校園與上學路的樹當觀察教材。時機：公園處預計年底改版行道樹路燈資訊網（研究筆記轉述，待核），新市府可直接把「民眾看得到前世今生、廠商在現場更新」放進改版需求。

**100 天時程**

| 期間 | 做什麼 |
|---|---|
| 第 1–30 天：盤點 | 成立跨局處小組；盤點樹籍、核准、標案資料流；選兩個試辦案；訂樹木編號與事件資料標準；整理 114–115 年逐樹移除紀錄；公開東門案檢討與新 SOP 草案 |
| 第 31–60 天：資料與 SOP | 試辦案核准清單與施工範圍接上樹木編號；契約補充條款；試作樹牌 QR；民眾回報審核分工；資安與個資評估；需求提供給資訊網改版 |
| 第 61–100 天：試辦啟動 | 兩案上線；試辦區開放民眾關心與回報；里長說明會、學校試行；第 90 天期中檢討；第 100 天公開試辦報告、決定正式預算 |

**試辦 KPI**
抽樣樹木事件 ≥ 95% 可連回樹籍與核准文件；非緊急施工後 3 個工作天內更新；每株額外工時 ≤ 10 分鐘；試辦案中處置與核准不符且未被事前攔下的案件 0 件（建議目標）。

## 遊戲化設計原則

- **給分理由看得懂**：每棵樹的上傳頁列出「上次有效更新、照片基本分、久沒人拍加分（上限）、回報分」，點數標「模擬，未經審核」。
- **不讓熱門區獨占**：「我附近」列出附近待更新的樹；排行頁有「各區缺資料比例」（樹籍調查超過 3 年未更新，真實欄位）。任務只指向人行道、公園等安全可到的公開位置，**不因高分引導任何人進入工地或車道**。
- **每張照片有後續**：同一棵樹的照片依時間排成序列、標「待驗證」；目前沒有市府串接，畫面明寫「示範，尚未送交市府」，不假造已受理。
- **里程碑優先、獎品輔助**：首次有效貢獻、持續更新同一棵、補足社區觀測三種里程碑；排行榜分本週、各區缺資料、全市累計，不只有終身總榜；獎勵商店寫明虛構企業、尚未承諾兌換。
- 設計參考見研究筆記（紐約志工樹木普查、FrogID、千葉 My City Report、波隆那 Bella Mossa 等），未來規劃：GPS 比對與點數審核拆開、贊助條件與資料退出寫進合作規格、同時評估有效／持續／公平、配置線下參與與承辦能力。

## 造假賺點數的預防機制（規劃，黑客松版未實作）

- 照片 EXIF 位置可以偽造，所以要和拍攝當下的瀏覽器定位、拍攝時間交叉比對。
- 同一張或很像的照片重複上傳：感知雜湊比對。
- 每人每棵樹冷卻時間、每人每日上限。
- 帳號綁手機。
- 移動速度異常（短時間內跨區上傳）暫停計分。
- 點數先「待確認」，由其他人之後上傳同一棵樹、或隨機人工抽查確認後才入帳。
- 排行榜前段人工審核。
- 獎勵用抽獎機會而非直接換現金，降低造假誘因。
- 未來：照片 AI 判讀是否真有樹、是否同一棵。

GPS 的限制：城市裡手機 GPS 誤差常有 5–20 公尺，相鄰行道樹間距可能更小，所以 GPS 只用來篩「附近的候選樹」，最後由使用者點選確認。部分手機或瀏覽器在選照片上傳時會拿掉定位（未驗證），所以退回用瀏覽器當下定位。

## 限制與已知問題

- **點位誤差**：樹木點位是人工調查打點，常有公尺級誤差；行道樹調查日期多在 2022–2024 年，之後移除或補種的樹不會反映。
- **推薦種樹點未現勘**：「最可能是空穴」只是書面比對，其中約 5,245 個整排都比對不到樹，比較像樹木資料沒登錄到該路段；地圖上已把這類點淡化，但仍會顯示。地下管線、土地權屬、無障礙淨寬都沒評估；人行道寬度欄位是不是淨寬也還沒確認。推薦數也不能拿來和「2025 年移除 3,164 棵」互相對照。
- **沒有真實登入**：廠商登入是示範帳號；民眾回報不需帳號，沒有內容審核，只適合 demo。伺服器有基本防護：每個 IP 每分鐘最多 10 筆、事件總數上限、只收資料裡存在的樹籍編號、點數由伺服器計算、比對距離只存級距（≤15 m／≤40 m／更遠）不存精確值。
- **點數存在瀏覽器**：「我的樹」與點數存在使用者自己的瀏覽器，換手機就不見，也可以被竄改。
- **樹齡是粗估**：依胸徑一律每年 1.6 公分推算，不同樹種差很多。
- **資料量**：樹木資料約 12 MB（伺服器以 gzip 傳送），舊手機首次載入可能較慢。

## 隱私與合規

- **不收真實個資**：不需註冊；回報只填暱稱，畫面提醒不要填真實姓名；「我的樹」與點數只存在使用者瀏覽器。
- **照片去 EXIF**：GPS 只在瀏覽器裡讀一次做比對、不上傳原始座標（只送距離與比對結果）；之後重新編碼移除全部 EXIF，伺服器端再剝一次 JPEG metadata 區段；只接受 JPEG。畫面提醒不要拍到路人的臉或車牌（目前沒有自動遮蔽）。
- **沒有爬取或掃描市府系統**：開放資料以正式下載連結一般下載；行道樹路燈資訊網（geopkl.gov.taipei）只在研究階段以一般請求取得首頁一次、確認有哪些查詢介面，沒有呼叫其查詢端點、沒有爬取；沒有做任何壓力測試。
- **虛構角色**：模擬的廠商、企業、使用者都是虛構名稱，不冒用真實企業或真實人物。
- 開放資料依政府資料開放授權條款第 1 版使用，標示提供機關如上。
